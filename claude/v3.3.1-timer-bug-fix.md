## Executive Summary

Fixed a severe bug affecting all timed game modes where timers reaching 0 seconds caused violent screen flickering and overlapping audio, rendering the app unusable until browser refresh. The issue affected Monster Race (timed mode), Advanced mode, Multiplayer sessions, and Squad Battle modes.

---

## Bug Description

### User-Reported Issue
When playing Monster Race (timed challenge) mode:
1. User starts game and timer counts down
2. When timer reaches 0 seconds, severe issues occur:
   - **Screen flickering violently** between game screen and results screen
   - **Audio overlap** with music tracks playing over each other creating harsh noise
   - App becomes unresponsive
   - Only resolution is to refresh the browser

### Root Cause Analysis

The bug was caused by missing state guards in timer logic that allowed the `endGame()` function to be called multiple times when timers reached zero:

1. **Single-Player Modes (Timed & Advanced)** - `App.js:1708`
   - Missing `gameActive` guard in timer effect
   - Effect would re-run with `timeLeft === 0` and `gameActive` still true
   - Multiple calls to `endGame()` before state updates completed
   - Result: Multiple `playEndMusic()` calls and multiple `setGameMode('results')` calls

2. **Multiplayer Mode** - `App.js:1676-1686`
   - Even worse: `setInterval` timer continued firing every second
   - Once `remaining === 0`, `endGame()` called repeatedly every second
   - No mechanism to prevent continuous execution
   - Result: Exponential audio overlap and continuous mode switching

3. **Squad Battle Mode** - `App.js:1699-1702`
   - Similar pattern with potential for duplicate calls
   - Also called non-existent `playSound('end')` (silently failed)

4. **Squad Survival Mode** - `App.js:1772`
   - Called non-existent `playSound('end')` (harmless but unnecessary)

## Technical Investigation

### Timer Logic Architecture

The app uses a single `useEffect` hook (lines 1663-1719) to manage all timer logic with different behaviors:
- **Multiplayer**: `setInterval` with server timestamp synchronization
- **Squad Battle**: `setTimeout` with continuous countdown (no pause)
- **Single-Player**: `setTimeout` with feedback pausing

### Dependency Array Issue

```javascript
}, [gameMode, timeLeft, gameActive, feedback.show, endGame, isMultiplayer, userRole, sessionData]);
```

When `timeLeft` changes to 0, the effect re-runs. If `endGame()` is called without state guards, it can execute before React batches the state updates from the previous call, creating a race condition.

### Sound System Review

Found that `playSound()` only supports these types:
- `'submit'`, `'correct'`, `'incorrect'`, `'click'`, `'countdown'`, `'countdownFinal'`

The code was calling `playSound('end')` in 3 places, which silently failed since no handler exists for `'end'`.

## Solutions Implemented

### 1. Single-Player Timed & Advanced Modes (Line 1708)

**Before:**
```javascript
} else if ((gameMode === 'timed' || gameMode === 'advanced') && timeLeft === 0) {
  endGame();
}
```

**After:**
```javascript
} else if ((gameMode === 'timed' || gameMode === 'advanced') && timeLeft === 0 && gameActive) {
  endGame();
}
```

**Impact**: Prevents `endGame()` from being called multiple times by checking if game is still active.

### 2. Multiplayer Mode (Lines 1676-1686)

**Before:**
```javascript
setTimeLeft(remaining);

if (remaining === 0) {
  if (gameMode === 'teacherMonitor') {
    setGameActive(false);
    playSound('end');
  } else {
    playSound('end');
    endGame();
  }
}
```

**After:**
```javascript
setTimeLeft(prev => {
  // Only trigger end game once when transitioning from >0 to 0
  if (prev > 0 && remaining === 0) {
    if (gameMode === 'teacherMonitor') {
      setGameActive(false);
    } else {
      endGame();
    }
  }
  return remaining;
});
```

**Impact**: Uses transition detection to only trigger game end once when timer crosses from >0 to 0. Removed non-functional `playSound('end')` calls.

### 3. Squad Battle Mode (Lines 1699-1702)

**Before:**
```javascript
} else if (timeLeft === 0) {
  setGameActive(false);
  playSound('end');
  // Results will be shown by the component when timeLeft === 0
}
```

**After:**
```javascript
} else if (timeLeft === 0 && gameActive) {
  setGameActive(false);
  // Results will be shown by the component when timeLeft === 0
}
```

**Impact**: Added `gameActive` guard for consistency. Removed non-functional `playSound('end')` call.

### 4. Squad Survival Mode (Line 1772)

**Before:**
```javascript
if (gameOver && squadData.isStarted) {
  playSound('end');
}
```

**After:**
```javascript
if (gameOver && squadData.isStarted) {
  // Game over - no sound needed (end music plays via playEndMusic)
}
```

**Impact**: Removed non-functional sound call with explanatory comment.

## Lessons Learned

### Root Cause Pattern
Timer effects with state changes in callbacks must have guards to prevent:
1. Multiple executions during state transition periods
2. Continuous execution in `setInterval` loops
3. Race conditions when multiple state updates occur

### Best Practices Applied
1. **State-based transitions**: Use `setState(prev => ...)` for transition detection
2. **Guard clauses**: Always check `gameActive` before triggering game-ending logic
3. **Dead code removal**: Remove non-functional calls to prevent confusion
4. **Comprehensive testing**: Review all timer-dependent code paths

### Prevention Strategy
For future timer-based features:
- Always include state guards in timer callbacks
- Use transition detection for continuous timers (`setInterval`)
- Test edge cases when state changes rapidly
- Document timer behavior clearly
